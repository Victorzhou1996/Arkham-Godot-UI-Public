# 《狂热之夜》与《敦威治遗产》：UI 与交互改进建议

2026-11-18 · 设计评审，非缺陷清单或实施记录。依据为当前 Godot 项目源码、已有牌桌截图和试玩记录；本轮没有启动游戏。下文的验收项是建议做的试玩，不是已通过的测试。

**结论：保留“地图就是牌桌、手牌就在面前”。第一轮先解决三件事：找得到轮到谁点哪张牌，分得清预览和真正提交，看得懂规则刚刚结算了什么。** 这三件事比再加一层菜单或先重画敦威治八张背景更值得做。

## 一、先改两套战役共用的三个交互

### 1. 用“等待谁”定位卡，不用它替玩家发动

- **建议：**等待标签写成「等待黛西 · 选择响应（2）」。悬停或点开列出可操作卡名；选中名字只滚动、展开并定位该卡，真正发动仍点卡。两张同名卡加位置或持有者，例如「放大镜 · 罗兰 · 左手」。列表只取当前座位可见且规则实际提供的选择；非卡牌选择直接写「选择一名调查员」，不要伪造卡名。
- **折叠也不能藏住行动：**如果能力来自密谋、场景或资产下方的附属牌，给可见的宿主加静态细框和数量。定位时只展开这一叠，不把全桌折叠牌都弹开。已自动确认的强制入口，在来源旁短暂写「强制 · 卡名」即可；需要选目标、支付、排序时停下来。信息同时进已有记录，不叠多条吐司。
- **怎样算好用：**在一局有两个待响应角色、其中一张卡被折叠的局面，从等待标签找到正确卡，不试点其他卡；关闭提示后，检定、资源和行动数都没变。

### 2. 把检定设计成“比较 → 选牌 → 确认”

- [列车检定截图](../evidence/board/02159.png)里，空投牌框占了面板的大半，而真正能投入的牌在屏幕底端。空框可先收成「点选或拖入手牌」，有牌再展开。扇形手牌保留：合法牌稍微上提，不合法牌仍可阅读。点选和拖入应得到同一份**待投入**清单，提交前可以点回。
- 数值直接写「当前 4 ＋ 待投入 2，对抗 3」，按钮随状态变成「投入 1 张并开始」或「不投牌，开始检定」。为他人投入时，按钮应写「确认我的投入」，不能让人误以为自己会替主检定者抽标记。若概率只是估算，明确写「约」，不让一个醒目的百分数取代规则信息。
- **怎样算好用：**试一次零投入，再试一次选两张、撤一张、确认；每一步都能说出哪张只是选中、哪张已被接受。多人检定能看出还在等谁。

### 3. 分配伤害或恐惧时，第一眼看到“给谁、给什么”

- [午夜假面截图](../evidence/board/01120.png)中，两张相同的黛西头像分别代表伤害和恐惧。信息都有，但第一眼像是在选两个人。建议同一承受者只出现一次，其下分两行「伤害」「恐惧」；上方写剩余数量。例如「还要分配：伤害 1、恐惧 0」。颜色辅以图标和文字。
- 有多个合法对象时才强调选择；核心如果逐项询问，界面也逐项提交，不把不同规则时点合成一次批量操作。唯一去处已自动处理时，在承受者旁留结果，不额外要一次确认。
- **怎样算好用：**同一人同时受伤害和恐惧、以及有盟友能承受其中一项，两种情况都不用比较重复头像，也不会把恐惧错当伤害。

## 二、这次补充：从开局到下次接着玩的六个细节

| 环节 | 现状或设计依据 | 建议及试玩判据 |
|---|---|---|
| 新手第一回合 | [现有引导](../app/Scripts/Table/TableScreen.Coach.cs)会教拖牌和点出口；出口按另一个地点按钮寻找，这个条件本身不等于“规则允许移动”。 | 只给当前确实可执行的动作贴提示，一次一个。开局没有合法出口时，不教移动；出现合法出口后，提示上的地点必须真的能去。不要替玩家挑“最佳”行动。 |
| 地图上的点击、拖动、读卡 | [地点输入](../app/Scripts/Table/TableScreen.Board.cs)在左键按下时进入地点操作，右键读卡。地图本身又可平移、缩放。 | 区分按下与松开：从地点起拖超过小段距离就是平移，不触发行动；轻点才走原有快捷操作。给读牌一个无需悬停或右键的入口，但别把所有桌面操作都改成双击。验收：从同一地点分别轻点、拖地图、只读卡，三次结果不同且无误移动。 |
| 窄窗与较大字号 | 已有界面缩放、减少动效和静音设置；此前记录过顶栏文字与头像、地点与装备槽互相遮挡。 | 空间不够时，先收起说明和空槽，不先缩小卡名、等待席位及确认按钮。待操作附属牌收成可点的叠层，展开后至少有一张完整可读；不要靠拉高整个资产区找牌。用 1280×720、115% 缩放、至少六张手牌试一次，主操作仍应可见。 |
| 多人交接与连续结算 | “谁的回合”“目前查看谁”“现在谁回答”可能是三个人；已有敌人攻击反馈和游戏记录。 | 只有回答者与当前视角不同时，显示一句「罗兰的回合，等待黛西响应」及定位入口。连续效果讲清来源与结果，例如「食尸鬼攻击 → 黛西承受 1 伤害」；优先在已有对象旁反馈，不为每步加整屏动画。静音、减少动效时，也能从文字看出谁受了什么影响。 |
| 继续调查与撤回 | [继续调查列表](../app/Scripts/Screens/ContinueDialog.cs)显示标题、调查员和“进度 N 步”；[撤回菜单](../app/Scripts/Table/TableScreen.History.cs)已有上一步、行动、回合、整轮和剧本起点。 | 列表先写可辨认的章节和停点，如「午夜假面 · 调查阶段」或「第一章结束 · 等待罗兰升级」，步数降为次要信息。优先用现有摘要，不为画列表重放全档。撤回菜单可多写一句目标，如「回到罗兰本回合开始」；只给大跨度撤回保留确认。验收：两个同名战役不必逐一进档辨认。 |
| 幕间牌组升级 | 已有保持牌组、经验计算和实际换牌流程，没必要再做一个编辑器。 | 在原确认区给简短差异：「移出 .45 自动手枪 ×1；加入 警徽（2）×1；花费 2，余 0」。明确这是哪位调查员，核心接受后再显示“已升级”；拒绝时保留草稿和原因。验收：一人保持、一人升级，回到幕间仍能分清谁已完成，原牌组不因预览改变。 |

## 三、逐关建议：同一套牌桌，不同的信息重点

这里建议的是呈现方式，不是改变剧本规则。地点、敌人、人物及胜利区内容均以玩家当前有权看到的信息为限。

| 战役／剧本 | 最值得突出的信息 | 一个具体改法 |
|---|---|---|
| 0 · 聚集于此 | 房间刚刚如何连通 | 保留宅邸剖面；新房间出现时，只突出新连接一次。已揭示、可阅读、当下可移动是三种不同状态，不共用一种亮边。 |
| 0 · 午夜假面 | 城区全局与异教徒进度 | 让顶部进度打开已发现／已进入胜利区的名单；点仍在场者即可定位。缩小时先保住街区名和调查员位置，而非卡图尺寸。 |
| 0 · 地底噬魔 | 相似树林间的方位 | 选中调查员时加强其所在地点和相邻连线。保留未知地点的神秘感，不能用提前显示背面文字来解决辨路问题。 |
| 1 · 课外活动 | 校园各处与当前调查目的 | 序章只用已公开剧情解释为什么去校园。进场后点当前目标，可定位其中已公开、可识别的地点或人物，不给最优路线。 |
| 1 · 百赌百胜 | 场所状态变化前后有何不同 | 沿用同一张地图；发生公开状态变化时，用一句话和局部标记提示哪些已知对象改变，不让玩家靠重新试点全场发现变化。 |
| 1 · 博物馆之夜 | 地图上与地图外不是一回事 | 给“虚空”等特殊放置区一个独立入口，与房间明显区分；公开对象从那里进入地图时，提示它落在哪个展厅。 |
| 1 · 疯狂列车 | 朝向，以及车厢脱落后的相对位置 | 固定车头方向；脱落只在原处反馈，不把整列车重新居中。关掉动效后仍能辨认当前车厢和前进方向。 |
| 1 · 血色祭坛 | 哪些人物已知、哪些仍未知 | 汇总已公开的人物状态，让已知且在场的人物可以定位；未揭示的身份不展示头像或名字。 |
| 1 · 无人知晓 | 敌人、调查员、地点的相对位置 | 点已出现的敌人时突出其所在地点。若同地有多名敌人，把卡名列开让玩家选，不让最上方的头像吞掉其他点击入口。 |
| 1 · 毁灭之地 | 朝山顶推进的空间方向 | 让山脚到山顶的方向稳定，把“目前相邻”和“目前能进入”区分开；不标示未公开的正确道路。 |
| 1 · 迷失时空 | 地图变化后仍能找到自己 | 地点增减时优先保持当前调查员的屏幕位置，只标出变化的地点与连线。已有“全图”供玩家主动重取景；此项应等真实第八章局面再定细节。 |

## 四、建议实施顺序与首轮验收

1. **先做共用操作。** 用《午夜假面》试等待定位、多人交接和伤害分配；用《疯狂列车》试投牌、地图拖动和视角稳定。各用一张普通窗口和一张窄窗口观察，不把自动通关当作这些交互的验收。
2. **再接回战役前后。** 用同一组隔离档案完成「继续调查 → 一人保持牌组、一人升级 → 下一章 → 返回列表」。确认玩家能认出哪一局、哪个人、哪项改动已生效。
3. **最后逐关补特有呈现。** 优先列车脱落、博物馆特殊区域和迷失时空地图变化。未取得真实局面的，不凭想象重写。暂不建议先画八张大背景、增加常驻任务栏，或给每次自动效果加确认窗。

**首轮是否值得保留，看三个问题：**不翻日志，玩家能否指出现在等谁点哪里？读卡、拖地图或暂选一张手牌，会不会意外提交？一次自动结算或地图变化后，能否说出谁、在哪里、发生了什么？
