## 发现

**经 Yunke 确认，本轮剩余 2 条阻塞、3 条重要意见。** 两条阻塞均在战役升级环节。带丽塔的合法牌组被客户端拒绝，经升级接口提交的三种不合法牌组进入了下一章。

- **开局构筑**。Yunke 确认与 HTML 版一致，开局允许使用含经验卡的牌组，只查构筑合法性，开局 XP 校验免除。罗兰带 4 XP 霰弹枪入场的回执符合该规则，原阻塞撤销。
- **合法升级被挡**。首章剧情奖励丽塔令白名单拒绝正常升级。隔离对照证明保留丽塔、买警徽可以由 DLL 正常执行，警徽在之后两章出现。
- **非法升级被接受**。从首章后的同一个黛西升级问题复制出三条隔离分支。超预算、跨职阶和缺牌的状态均被提交，并在《午夜假面》正式开局中保留。
- **接续与可用性**。核心拒绝过期提交可防止重复扣行动。前端错误分支未重新加载问题，计时器也没绑定席位。整图能读取未揭示地点的正面。攻击框的固定数值没有覆盖霰弹枪按差值决定伤害的情况。

### 开局与操作实测回执

- 4 XP 霰弹枪样本：进入书房调查 `seq=12`，牌堆 1，手牌 0，已获／已花经验 0／0。
- 书房检定一个样本：罗兰投入《超感知》，技能值 3→4，撤回 4→3，再投入。核心结算 `SucceededBy=1`，投影为“成功 · 超过 1 点”，提交后行动 3→2、书房线索 4→3。
- 座位：同序号可同时存在罗兰开始检定和黛西投入的不同问题。对同序号的错误席位提交应用结果收到拒绝，回到正确席位仍可应用。取资源 `seq=14→15` 后重投 `14`，得到 `StaleLocalState`。
- 基础游戏 `r10` 已确认到第三章结局，但有 180 次过期状态异常。`r11` 到第三章后达到自动游玩步数上限，日志有 543 次异常。这些既有日志不能证明每次异常的成因相同。

## 建议

1. 按 Yunke 确认的方案，以现有 build 系统统一牌组合法性校验和战役升级的构筑检查。开局校验职阶、张数、同名上限和必带牌等限制，合法经验牌组可在没有独立剧本预算字段的情况下使用。升级提交核对本次变更所需经验和该席位余额，并保留核心已发放的剧情牌。复测合法剧情牌、跨职阶、超预算、少一张和同名超限。涉及 DLL 改动时 **需 Yunke 决定**。
2. 将失败响应处理和计时器对准当前题目、席位及序号。以 `r10` 的撤回重试链路复跑连续回合，记录拒绝、重读和可以继续三个状态。继续沿用 [升级失败丢草稿意见](20261118-1003-战役升级被拒时丢失编辑草稿.md)。
3. 未揭示地点只读当前允许的面。逐项对照伤害预览与核心伤害事件，覆盖霰弹枪、大砍刀在多敌交战时、致命打击、敌人伤害／恐惧与响应。通过概率当前对“再揭示一枚”按固定 −2 作近似，精确概率和实际抽取前画面仍需专项取证。
4. 剩余验收按三关高风险分支做小型隔离局面：首章打赢后的领队结局与房屋烧毁联动、第二章盘问与过午夜、第三章三条结局。每条都留请求、回执、下一步与对应 UI 依据。
