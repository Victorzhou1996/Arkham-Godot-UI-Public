# 默认启动入口指向禁止读写的数据目录

## 发现

实际检查时刻：2026-11-18 12:21:03 +08:00。本轮仅阅读工作区源码和启动脚本，没有启动游戏，没有进入或读取 `userdata/`。

`启动新版.cmd` 未传 `--data-root`。`App._Ready()` 因而把数据根目录设为本工作区的 `userdata/`，调用 `Directory.CreateDirectory(DataRoot)`，再交给 `Services.Start`。服务使用该目录的 `decks.json`、`settings.json`，后端创建该目录的 `gathering.sqlite` 存储，缺少示例牌组时还会保存牌组。

这是默认入口可直接到达的持久化路径，与 `SUPERVISION.md` 第 4 节“不读写任何 userdata/”的边界冲突，也不同于原计划 M6 指定的正常入口 `userdata-new/`。试玩入口则显式指定 `qa-data/trial`。源码足以确认默认入口的行为，但本轮可读日志中未找到默认入口实际运行的 `APP_READY data=…\userdata` 回执；**不据此断言实现者已在某时读写该目录，也不判定已有数据被改动**。

## 证据路径

- `启动新版.cmd` 第 4、7 行：正常数据目录说明及未带数据根参数的启动命令。
- `启动新版试玩.cmd` 第 7 行：显式指定隔离数据目录。

- `engine/PrototypeBackend.cs` 第 31–41 行：目录创建及 `gathering.sqlite`。
- `docs/PLAN-20261117.md` 第 3 节 M6；`docs/SUPERVISION.md` 第 4 节第 3 条。

## 建议

**需 Yunke 决定**正常游玩的正式数据目录、默认入口的允许范围，以及现行隔离约定是否变更。决定前不要用默认入口进行本轮验收；如需测试，应由实现者使用已获授权、显式指定的隔离入口。获准修复后，让默认值和启动入口与批准的目录一致，并用启动日志说明实际数据根目录。不要为核查此意见而读取、迁移或删除现有 `userdata/` 内容。
