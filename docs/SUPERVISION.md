# 监督说明（给 Orca 中的 Claude）

本文件说明如何监督"新版原生前端"夜间工作。实现者是 Claude 应用里的一个会话（云端，通过桌面 App 操作本机），**不在 Orca 中运行，Orca 无法读取或向它发消息**。监督只能通过本目录的文件进行。

## 1. 位置
- 工作区：`G:\Python Project\Arkham UI\`
- 今日计划：`docs/PLAN-20261117.md`（里程碑 M0–M6 与任务编号）
- 进度：`docs/PROGRESS.md`（每完成一个任务或每 60 分钟至少更新一次，带时间戳）
- 证据：`evidence/<里程碑>/`（截图、日志、回执）
- 构建与运行日志：`jobs/done/<任务号>.*`
- 夜间助手心跳：`jobs/runner-alive.txt`（每 2 秒刷新时间）
- 最终报告：`docs/REPORT-20261117.md`（M6 生成）

## 2. 建议检查节奏（每 60 分钟一次）
1. `docs/PROGRESS.md` 最后更新时间是否在 90 分钟内。超过 → 记为"可能停滞"。
2. `jobs/runner-alive.txt` 是否在 10 分钟内。超过 → 夜间助手可能已关闭或电脑休眠/锁屏。
3. 当前里程碑是否与计划时间相差超过 2 小时。
4. 进度里标为完成的任务，是否有对应证据文件（截图/日志）。没有证据的"完成"要指出。
5. 状态用词是否合规：只允许 `未做`、`进行中`、`已做未验证`、`待你验收`。出现"已验证"即为违规（只有 Yunke 能记）。
6. 红线检查（见第 4 节）。

## 3. 如何提出意见
- 每条意见写成一个文件：`docs/review/YYYYMMDD-HHMM-<简短主题>.md`，包含：发现、证据路径、建议、严重程度（阻塞/重要/建议）。
- 实现者在每个任务开始前读取 `docs/review/`，处理后在原文件末尾追加"处理结果"。
- 意见是审查参考，由实现者判断后处理；需要拍板的事项（范围变化、删除、规则相关）应通知 Yunke，由 Yunke 在 Claude 对话里决定。

## 4. 红线（发现即标"阻塞"并通知 Yunke）
- 修改了 `G:\Python Project\ArkhamHorrorLocal-WinDeploy-20260712\` 下任何文件（该仓库对本工作只读）。
- 改动规则 DLL、存档格式、规则身份、回答权限；`runtime/` 中 DLL 的 SHA256 与 `docs/SOURCES.md` 记录不一致。
- 读写任何 `userdata/`、profile、QA 档案（新版只用本目录 `qa-data/`）。
- 发布、上传、打包、修改桌面快捷方式。
- 结束了不是夜间助手启动的进程。

## 5. 监督方不要做的事
- 不要修改本目录下 `docs/review/` 以外的任何文件。
- **不要往 `jobs/inbox/` 放任何文件**（那是实现者给夜间助手的任务队列）。
- 不要关闭标题为 "Arkham UI night runner" 的 PowerShell 窗口。
- 不要在夜间操作桌面（鼠标、键盘、开关窗口），会与实现者的实机检查冲突。

## 6. 早上给 Yunke 的摘要建议格式
5–10 行：完成到哪个里程碑、哪些检查通过、哪些失败或未测、发现的红线问题（如有）、建议 Yunke 优先看的截图路径。
