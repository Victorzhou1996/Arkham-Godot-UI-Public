# 联机 + 一人多控：设计思路（2026-11-23）

Yunke 的例子：A、B、C 三人联机，想玩四人局。第四名调查员的牌组由建房的人选；这个座位的控制权可以交给 A / B / C 中任意一人，或者大家一起控制，或者交给 AI（AI 现在先留入口）。

## 结论：能做，改动集中在"房间"和"座位归属"两处

现在的联机已经具备一半条件：
- **规则核心不关心谁在操作。** 开局时座位数就是调查员数（`CreateNewGame(seats, …)`），4 个座位、3 个人完全可以。
- **牌桌已经支持一台机器管多个座位。** 本机轮流操作就是这样：`TableScreen.AdvanceInner` 会自动切到"归我管、正在被问"的座位，联机时用 `OnlineGame.Mine(seat)` 判断。只要 `Mine` 对两个座位都返回"是"，牌桌就会像本机多控那样在两人之间切换。
- **同时点击不会打乱局面。** 主机执行每个操作前都核对局面序号（`OnlineGame.Serve`：`seq != basis.Sequence` 拒绝）。所以"大家一起控制"时，两人同时点，只有先到的生效，后到的会看到"牌桌已更新"，然后重新读取。

真正绑死的是三处：
1. **房间里"一人一座"。** EOS 房间的每个成员只有一个 `Seat` 属性；开局条件 `CanStart` 要求"每人入座、每人选一个调查员"；开局时"座位数 = 入座人数"。
2. **座位归属只有一个人。** `owners: 座位 → 成员 id`（"" = 主机）。主机校验客人的操作用的是 `owner == from`。
3. **续玩存档时按成员找座位。** 这样一来，多出来的那个座位无人认领。

## 方案

### 1. 房间：加"托管座位"
- 建房的人在空座位上点 **"添加调查员（托管）"**，弹出和准备画面相同的调查员群像，再从**建房人自己的牌组库**选牌组。牌组只存在主机上，因为开局时由主机回答该座位的 ChooseDeck（现有的 `HostSteps`），不用传给别人。
- 托管座位写进**房间属性**（主机所有，例如 `SEAT3 = {调查员, 牌组名, 控制者}`），所有人在房间里都能看到"调查员 4：XX · 由 B 控制"。
- 每个座位（包括真人入座的）都有一个 **"控制权"下拉框**，只有建房的人能改：
  - 建房者 / 玩家 B / 玩家 C（房间里任何一人）
  - 大家一起
  - AI 控制（灰色，标"开发中"）
- 开局条件改成：每个座位都有调查员和牌组，每个托管座位都有控制者。座位数取"已占用的座位"，不再是"入座人数"。

### 2. 座位归属：从"一人"扩成"一组人"
- 每个座位的控制者取下面三种之一，开局消息里一起发给所有人：
  - `owners: 座位 → 成员 id`
  - `"*"`（大家一起）
  - `"ai"`
- `Mine(座位)` 改为：控制者是我，或者是 `"*"`。
- 主机校验改为：控制者是发请求的人，或者是 `"*"`。`"ai"` 座位只有主机自己能操作。
- **牌桌显示控制者。** 队友头像下写"B 控制 / 大家一起"；等别人操作时，提示写成"等待 B 操作（调查员 4）"。
- **"大家一起"的座位不自动切视角。** 否则每个人的屏幕都会被拉过去。改成在提示条上显示"共同控制的 XX 在等待操作"和一个"去操作"按钮；如果自己没有要回答的问题，再自动切过去。

### 3. 局中调整与掉线
- 建房者的牌桌菜单里加 **"调整控制权"**，随时可以把某个座位改给别人。改完后主机向所有人广播新的归属表，各端重新读取。
- **有人掉线：** 他控制的座位临时归建房者，或者归"大家一起"（建房时可以选），他重连后再还给他。现在掉线的人的座位只能干等。
- **局间升级牌组：** 由该座位的控制者升级；"大家一起"的座位由建房者升级。

### 4. AI 入口
- 先只在下拉框里放一个灰色的 **"AI 控制（开发中）"**。
- 以后接入的方式：主机发现被问的是 `"ai"` 座位时，调用 `AiBrain.Decide(TableModel)` 代答。这个接口自动游玩已经在用，正在训练中。AI 只在主机上跑，客人不需要任何改动。

### 5. 存档续玩
- 联机局的座位归属（控制者、托管座位用的牌组）另外存一份文件，放在 `setups/` 旁边。
- 续玩时房间按存档恢复："调查员 4 · 由 B 控制"。建房者可以重新分配。

## 工作量与风险
- 主要改动在 `OnlineGame.cs`（归属模型、校验、广播）、`OnlineDialogs.cs`（房间里的托管座位和控制权下拉框）、`EosOnlineService.cs`（房间属性）、`TableScreen` 的提示和切换规则、牌桌菜单。规则核心不用动。
- 可以用现有的本机双开 TCP 测试（`--online-loop`）离屏验证：两台"机器"开四人局，测试托管座位、改控制权、大家一起控制、模拟掉线。
- 风险：
  - "大家一起"时同时点击，后到的操作会被拒，要把提示做得不刺眼。
  - EOS 房间属性单条有长度上限，所以托管座位只写摘要，牌组不放进房间。
  - 旧版本的客人不认识新的开局消息，版本门禁（不同版本不能联机）已经挡住了这种情况。

  - 掉线时座位暂归建房者，回来后自动归还（`RoomMembers`）。
  - 存档续玩时记住控制者（`setups/<id>.online.json`）。
  - 房间：空座位可以"添加调查员（托管）"，用建房者的牌组；每个托管座位有"控制"下拉框；AI 选项灰显。
  - 牌桌：
    - 队友头像左上角写控制者；
    - 先切到自己独占的座位，再切到"大家一起"的座位；
