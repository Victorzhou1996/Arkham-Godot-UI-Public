# 按顺序通玩 · 规则核对记录（2026-11-18）

Yunke 的要求："按顺序游玩基础和一循环，并且记录并修复错误和问题，尤其是 dll 后端规则是否都正确体现"。

状态：已做未验证（全部是程序化通玩 + 截图，真人鼠标未测）。

## 1. 方法

- 通玩：自动通玩走真实界面（和鼠标点击同一条路径），从主菜单开新战役，两人（狂热之夜：罗兰 + 黛西；敦威治：佐伊 + 吉姆），简单难度，章节之间走升级流程。
- 规则核对（新，`TableScreen.Audit.cs`，只在自动通玩时运行）：每一步把界面显示或界面自己算的数，和规则核心 DLL 给出的数逐项对比，日志里每项一行 `AUDIT_RULE <项目> ok|MISMATCH …`，不一致时把核心的原始记录存到 `<证据目录>/samples/`。核对项：
  1. **混沌袋**：准备界面写的袋子（`ChaosBagRules`）↔ 核心开局实际的袋子。
  2. **调查员数值**：选人界面写的四项技能和生命/理智（`SelectionStage.Stats`）↔ 核心的调查员。
  3. **当前技能值**：牌桌上显示的技能（含修正）↔ 核心开始检定时的技能值（没投入卡时）。
  4. **检定难度**：牌桌上显示的敌人战斗/躲避值、地点隐藏值 ↔ 核心检定的难度。
  5. **混沌标记数值**：前端按冒险参考卡写的表 ↔ 核心这次检定里每种标记的值（`valueBreakdown`）。
  6. **检定结果**：显示值 + 标记 − 难度 ↔ 核心的成功/失败差值。
  7. **卡牌费用**：手牌上显示的费用 ↔ 打出后实际扣掉的资源。
  8. **文字**：核心问题的标题、正文、每个选项都必须是中文。

## 2. 发现与修复

| # | 问题 | 原因 | 修复 |
|---|---|---|---|
| 1 | 聚集于此：骷髅标记的通过概率按 0 算，核心实际是 −1 | 与你交战的食尸鬼在威胁区，前端只数"放在地点上"的敌人；规则里交战的敌人也在你所在地点 | 检定进行时，通过概率和标记数值**直接用核心给的值**（`valueBreakdown`：每种标记的值、自动失败、自动成功、平局算失败、"成功超过 N 即失败"）；前端自己的表只在没有检定时作后备，后备也改为把交战敌人算在地点上（`EnemiesHere`） |
| 2 | 牌桌上调查员的四项技能只显示印刷值，资产等带来的修正（如 +1 意志）不显示 | 只读了核心的基础值 | 按 html 版 `Investigator.vue` 的算法把核心给调查员的修正加上（BaseSkillOf / SkillModifier / ActionSkillModifier / AnySkillValue / SetSkillValue）；和印刷值不同时变绿/变红，悬停写"基础 X，现在 Y" |
| 3 | 敌人的战斗/躲避/生命、地点的隐藏值不含修正 | 同上，只读印刷值 | 加上核心给敌人/地点的修正（EnemyFight、EnemyEvade、HealthModifier、ShroudModifier、SetShroud） |
| 4 | 顶栏目标文字很长时（聚集于此第二幕"灼热屏障"）伸到右侧头像下面，线索格被盖住 | 文字不换行也不截断 | 目标两行在栏内截断成"…"，完整文字在悬停浮窗里 |
| 5 | 地图上靠左、靠下的地点卡被"与你交战"一栏和装备槽格子挡住（课外活动"人文学大楼"只露出"文学大楼"，聚集于此的地窖被槽位盖住） | 地图全图框到了左侧栏和槽位下面 | 全图的范围改到交战栏右边、槽位上方 |
| 6 | 剧情页很长时（聚集于此未达成结局），"继续"按钮被挤出屏幕下方 | 正文不滚动 | 正文放进滚动框，最高占屏幕 60% |
| 7 | "已自动结算"提示盖住右上角密谋的"撤退"按钮 | 两者位置重叠 | 提示移到场景 / 密谋按钮下方 |

| 9 | Yunke 11-18：战役被做成了可以分开选关，准备界面每关一份固定引言 | 没按 html 版和规则核心的战役流程做 | 见 `docs/CAMPAIGN-STORY-LOGIC.md`：只能从头连续进行，引言和结局一律由核心按日志给出 |
