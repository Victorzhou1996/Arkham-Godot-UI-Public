# 基础游戏（狂热之夜）做下来碰到的问题总结（2026-11-18）

状态用词遵守 `docs/SUPERVISION.md`：本文所有条目均为 **已做未验证**，由 Yunke 验收标记。

用途：做下一个循环（敦威治遗产）之前，把基础游戏三关里踩过的坑归成类，每类写"现象 → 根因 → 以后怎么做"。逐条细节见：

- `docs/PLAYTEST-NOTES-01104.md`、`docs/PLAYTEST-ROUND2-01104.md`（Yunke 两轮试玩，共 36 条）
- `docs/EXPERIENCE-01104-GATHERING.md`（规则接口）
- `docs/SCENARIO-02-MIDNIGHT-MASKS.md`、`docs/SCENARIO-03-DEVOURER-BELOW.md`
- `docs/FRONTEND-DESIGN-NOTES.md`（设计规则，最高优先级在 §0）

## 1. 总原则（这次学到的，按重要性）

1. **不确定效果怎么做，先抄 html 版（0712 网页版）**。自己发明的做法几乎都被打回：标记翻转、检定中的标记效果、资产槽、日志翻译、强调符号都是最后照 html 版才做对。
2. **所有文字用官方中文**。场景名、剧情、结局、战役日志、卡名，一律从 html 版的 locale 和卡牌数据里取。自己翻的"吞噬者之下""零之循环"、自己写的介绍和结局标题都错了。找不到官方文本就如实说，不自造。
3. **规则只问核心 DLL**。前端不推断规则；Haskell 源码只做参考。凡是前端"替核心算"的地方（数量、费用、谁能选）都出过错。
4. **每一步都能撤回**，撤回后刷新随机种子。
5. **自动做的事也要让玩家看见**：自动结算前停一下、亮出来源；不能悄悄替玩家回答。
6. **改完要截图看**，而且要抓中途帧（动画）；能用 QA 脚本触发的就别等自动通玩撞上。

## 2. 问题分类

### 2.1 文本与本地化

| 现象 | 根因 | 以后怎么做 |
|---|---|---|
| 关卡名、战役名、介绍、结局标题是自己编的 | 没去查 locale | 新内容先查 `locale-zh.json` 的 `<campaign>.<scenario>.intro / resolutions / key`、`scenarioNames`、`campaignNames` |
| 记录里漏出英文（Revelation、Record "…"、must discard down to 8 cards） | 核心有些记录是英文纯文本 | 按 html 版 `gameLogLocalization.ts` 的规则翻译；QA 步骤 `scan-english` 扫全屏 |
| `【未汉化：log.attachesTo】` | 本地 locale 副本比 html 版旧 | 缺的官方词条放进 `locale-zh-extra.json`（原样复制，不覆盖已有词条） |
| `_引言 2_`、`_如果未达成…：_` 露出下划线 | 强调正则对中文边界判断错 | 照 html 版 `helpers.ts`：`_x_` 加粗、`*x*` 斜体 |
| "伤害点伤害和恐惧点恐惧"（缺数字） | 先把 `{damage}` 当图标换成文字，再填变量 | 先填变量、再去标记 |
| 复数写法"1点 \| {count}点"原样显示 | 没处理 vue-i18n 复数 | 按数量选形式 |

### 2.2 规则数据与核心接口

| 现象 | 根因 | 以后怎么做 |
|---|---|---|
| 怪物生命、推进费用显示错（人数倍数） | 漏乘 `PerPlayer`，或乘了两次 | 一律用 `TableModel.Calc`；核心给的总数直接用 |
| 推进第二幕卡住 | 策略没在非玩家窗口选推进 | 自动通玩策略要认识"推进按钮" |
| 升级时"保持牌组"被多扣经验 | 重新提交了开局牌组 | 保持牌组发 `UpgradeDeckAnswer`（牌组为空）；升级从核心存档里的当前牌组开始 |
| 升级按钮不出现 | 章与章之间没有当前场景编号 | 用"下一步是哪一关"判断 |
| 设置表单被前端悄悄用默认值回答 | 为了省事 | 有选项就给玩家看；没选项才发默认值 |
| 混沌标记效果/通过概率每关不同 | 冒险卡数值按关卡 | 每关的标记数值要单独配（`TableScreen.Odds.cs`） |

### 2.3 呈现与交互（Yunke 试玩反馈最多的部分）

| 类别 | 典型问题 | 以后怎么做 |
|---|---|---|
| 看不出该点哪里 | 推进场景、检定确认、分配线索都没有明显指示 | 可操作的东西要有按钮或闪动；不能只靠边框变亮 |
| 选项只能从屏幕边角选 | 选调查员只能点左上头像 | 指向调查员/卡牌的选项一律在中央画成小卡 |
| 来源不清 | 武器发动后选敌人，不知道是哪张牌 | 从来源牌画箭头到每个可选目标 |
| 顺序乱 | 神话阶段横幅、翻牌、效果同时出现 | 先横幅，再逐张翻牌，最后才是效果；全依记录条目 |
| 自动结算看不见 | 怪物攻击瞬间结束 | 攻击者发光摆动、停 1 秒；停顿时牌桌忙碌，防止重复提交 |
| 布局重叠/挤出屏幕 | 顶栏重叠、准备界面按钮被长介绍挤出去 | 先算布局预算；长文本限高滚动 |
| 视觉细节反复丢失 | 小卡底部黑色渐变两次消失 | 用色条实现，改卡牌后截图确认 |
| 无人控制的资产不显示 | 丽塔在客厅看不到 | 地点上的无主资产要画出来、可点 |
| 风格 | 华丽边框、硬边、实心描边被否 | 极简＋黑色渐变；边缘渐变到透明 |

### 2.4 工程与验证

| 现象 | 根因 | 以后怎么做 |
|---|---|---|
| 弹窗偶尔加不上、真实游玩会卡死 | 父节点忙时 `add_child` 失败 | 失败时下一帧重试 |
| 攻击停顿期间提交导致状态过期 | 停顿时界面仍可点 | 停顿期间 `busy` |
| 整段代码改动没编译就交接 | — | 每次改完都编译并截图 |
| 自动通玩打不到某些分支（R1/R2 选择、两人分摊） | 策略太弱 | 用 QA 步骤直接打开存档的某一步（`open-at`）去截图 |
| 别人的进程差点被杀 | 按进程名杀 | 只杀自己按数据目录启动的进程 |

## 3. 带到下一个循环的检查清单

每做一关：

1. 官方文本：关卡名、介绍（可能多段）、结局标题与正文、战役日志词条、标记效果文字，全部查 locale。
2. 场景数据 JSON：名字、地图名、地点背景、目标句子、结局图。
3. 混沌标记数值（简单/标准、困难/专家）。
4. 特殊问题类型：自动通玩审计，看有没有前端没处理的问题/选项类型。
5. 剧情选择、幕间（interlude）、战役日志的特殊记录。
6. `scan-english` 扫一遍。
7. 截图：准备界面、牌桌、地图、检定、结局。
8. 文档写进 `docs/`，状态一律"已做未验证"。

## 补充（2026-11-18，Yunke 指出）

- **战役是连续的，不是选关。** 新循环一律只能从头开始、按核心的战役步骤一章接一章；准备界面只显示路线。每章的引言、结局、幕间、尾声都由核心按战役日志选定后发来，前端不能给每章写死一份引言，也不能提供"从第 N 章开始"。核心标为不适用的段落照 html 版显示为灰色。详见 `docs/CAMPAIGN-STORY-LOGIC.md`。
- **规则数字一律以核心为准。** 检定中的混沌标记数值、通过概率用核心发来的 `valueBreakdown`；技能、敌人数值、隐藏值都要加上核心给的修正。前端自己照冒险参考卡写的数值表，在敦威治里对错参半（`docs/PLAYTEST-RULES-AUDIT-20261118.md`）。
- 每做一个新循环，跑一次带规则核对的自动通玩（`TableScreen.Audit.cs`：`AUDIT_RULE` / `AUDIT_STORY`），逐页看核心读出的剧情顺序。
