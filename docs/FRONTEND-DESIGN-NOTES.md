## 0. 最高优先级（Yunke 指示，2026-11-17）

- **不确定某个效果该怎么做时，直接使用 0712 网页版（html 版）里的特效。** 网页版源码：`ArkhamHorrorLocal-WinDeploy-20260712/classic-fast-20261117/frontend/src/arkham/components/`（只读参考）。先去那里找现成做法，再照着在 Godot 里实现；不要自己另想一套。
  - 已按此做过的：混沌标记翻转（`Token.vue`：空白背面转两次后显示正面）、检定中的标记效果（`SkillTest.vue` 的 `token-effects`：符号标记显示效果文字，数字标记不显示文字）、资产槽（`Player.vue`：每个空位一个圆角格子，里面是类别图标）。

- **向 Yunke 汇报一律用中文（Yunke 指示，11-18）**：所有回复、进度汇报、总结、提问都用中文写；文件路径和代码标识符保持原样。
- **所有文本都要汉化，所有翻译都用官译（Yunke 指示，11-18）**：场景名、剧情、结局、战役日志、卡名等一律用 html 版的官方文本（`app/assets/data/locale-zh.json`、`core-cards.json`，均来自 0712 网页版）。不要自己编译名或剧情。找不到官方文本时如实说明，不要自造。界面上不能出现英文（例如记录里曾漏出 "Revelation"）。官方文本里的 `_x_`（加粗）和 `*x*`（斜体）照 html 版处理；本地词典缺的官方词条放在 `locale-zh-extra.json`，从 html 版原样复制。检查：QA 步骤 `scan-english` 列出屏幕上所有英文。
- **每张小卡底部必须有黑色渐变（时刻牢记）**：名字压在卡图上时，底部从透明到深色的渐变不能丢。它曾经因为渐变贴图不绘制而悄悄消失过一次；现在用色条实现（`CardView.BuildRedrawn`、`Ui.EdgeFade`），任何改动卡牌的地方都要截图确认这条渐变还在。
- **地图是牌桌的中心（Yunke 11-18）**：参考 html 版，所有地点始终摆在牌桌中央，可拖动、缩放，让玩家有全局概念；不要做成单独的地图入口。但不用原卡图，而是写实地图背景 + 交互小卡 + 浮窗（`TableScreen.Board.cs`，细节见 `docs/CYCLE-01-DUNWICH-LEGACY.md` §3.7）。
- **连线箭头**：选项来自某张牌（武器、医学教科书）时，从那张牌画箭头到每个可选目标；不要只靠目标发光。
- **所有按钮的背景边缘渐变（Yunke 11-18，全游戏统一风格）**：按钮底色是一块边缘融化的暗色，不要硬边方块；统一用 `Ui.SoftBox`（只有一圈宽模糊阴影，没有实底和硬边；选中或悬停时阴影带一点琥珀暖光，不画硬下划线）。App 设了全局主题，没单独指定样式的 Button / OptionButton 也默认如此。`Ui.MinimalButton` / `Ui.Button` 和牌桌选项按钮 `ChoiceButton` 已经改用它；新写的按钮也必须用它。
- **高亮蒙版原则（Yunke 11-18，凡是用蒙版做高亮的地方都适用：地图地点、选人群像等）**：
  1. 主体（地点或人物）一定要被蒙版完全覆盖。蒙版可以比主体略大，不必严丝合缝；宁可多盖一点背景，也不能让主体有一块没亮。
  2. 蒙版四周不要有锐利的边缘或尖角，用由亮到暗的渐变过渡，营造发光的效果。
  做法：着色器在每个像素周围一定半径内多点采样蒙版，取平均作为覆盖度，覆盖度略往外扩，再平滑过渡（见 `SelectionStage` 的场景着色器、`TableScreen.Board.cs` 的 `RegionLight`）。不要按蒙版边界硬切明暗，也不要沿边界描一条硬线。
- **选人群像的高亮 = 柔边剪影光（Yunke 11-18 定稿）**：试过两种做法都被否掉了：沿人物轮廓的蒙版太刻意；圆形聚光灯会照到旁边的人，人物也不居中。定下来的表现形式是：
  1. **形状跟着人物剪影走**：被照亮的是选中人物的整个剪影，不是一个圆形光斑，旁边的人不会被一起照亮。
  2. **边缘很宽、很软**：剪影之外是一圈宽光晕（约画面宽度 9%），光慢慢淡到墙和地板上，看不出明显的边界，也没有描边。
  3. **背景压暗但看得清**：其他人和房间降到约 50% 亮度，略微去色；信息面板那一侧再暗一些，保证文字清楚（暗化 76%）。
  4. **选中的人略偏暖**，其他部分保持原画色调。
  5. **换人时光会流过去**：上一个人淡出、下一个人淡入，大约半秒；悬停只有很弱的预览光。
  6. **镜头推进到人物中心**：中心是手动标在身体和头之间的点，不用剪影外框（伸出的手臂会把外框中心拉偏）；人物放在信息面板空出来的那半边的正中。
  做法（`SelectionStage.cs`）：`LightMaps` 把每个人的剪影缩到 1/4，每人一个通道（8 人以内两张 RGBA），模糊两遍（每遍约 37 像素）得到光照图；场景着色器读光照图做核心光，再在周围取两圈 24 个采样做宽光晕（`halo = 0.09`），两者取较大值；房间亮度 `mix(1, 0.5, spot)`。镜头中心见 `SpotOverrides`。新的群像只要有分人的颜色蒙版就能直接用；镜头中心不准时，在 `SpotOverrides` 里补一行。
- **按钮和面板 = 纯色 + 边缘柔光（Yunke 11-18 第六轮）**：所有按钮是一块纯色底，外面一圈同色的柔光，圆角，没有硬边框；平时是深色底，悬停或选中时是暖铜色底配金色柔光（`Ui.SoftBox`）。面板、笔记本、格子用同样的深色柔边底（`Ui.SoftPanel`）。首页菜单的悬停是一条发光的金色长条，两端渐隐，文字变深色（`Ui.GlowBar`）。
- **牌组工坊 = 炉石组牌界面的布局和动效，我们的画风（Yunke 11-18 第六轮）**：左边卡册一页 4×2，翻页箭头和页码；下方费用宝石和查找；右边按费用排序的牌组列表，底部张数和保存；加牌时卡飞进列表、带光点，移牌时那一行闪亮、卡飞回卡册，悬停一行显示整张卡。
- **地图模式 = 专心看地图（Yunke 11-18）**：Tab 在左上角小地图和地图模式之间切换。地图模式下，地图盖在所有牌桌元素之上，牌桌在后方模糊变暗；地图完整可见，只能放大不能缩到看不全。左上角小地图不能缩到比框小。点地点先推进，再点才执行；可以点的地点显示手指光标。
- **原图优先，不用滤镜重绘（Yunke 11-18）**：剧本和战役封面、场景和密谋的剧情配图都用原卡或 html 的原图，只裁出插画区（`tools/make_covers.py`、`tools/make_story_art.py`）；滤镜重绘太粗糙。
- **调查员小卡用 html 版素材**：`assets/ui/mini/<编号>.jpg`（来自 0712 网页版 portraits），不用插画裁切。

## 0.1 本轮（11-17 晚）定下的做法

- **边缘渐变到透明，不是渐变到黑色**：人物肖像四边用着色器淡出（`Ui.EdgeAlpha`），下面不再垫黑块。
- **资产格**：一格一个槽位，圆角矩形；有资产就放资产，空位放类别浅色图标（手部、背部、魔法、盟友、其他）。
- **起手换牌**：点牌只是选中/取消（牌抬起、标"换掉"），最后点一次"确认换掉 N 张"一起换。
- **每一步都能撤回**：撤回菜单第一项"上一步"（Ctrl+Z / U），抽完混沌标记后也能撤；跳过界面自己会自动回答的步骤。
- **神话阶段的顺序**：先阶段黑屏横幅，再逐张翻出神话卡，最后才出现这张卡的效果（检定或选择）；全程同一个楷体。
- **场景推进要有按钮**：可以推进时，目标条下方出现一个闪动的"推进场景"按钮，不能只靠边框变亮。
- **悬停浮窗**：场景和密谋都有；浮窗高度只跟文字一样高。

## 1. 黑色块与渐变

- **外侧渐变，不用硬边**：深色面板的外侧要渐变融入场景。做法：深色核心 + 向外扩散的柔和阴影（`StyleBoxFlat.ShadowSize`，阴影颜色与面板相同），不要在面板内再铺一层边缘渐变条（会在四角留下接缝）。
  - 在哪：左下角调查员区域 `TableScreen.Layout.cs` PlayerArea。
- **肖像边缘也渐变**：肖像在黑块内时，四边用渐变条（`Ui.EdgeFade`）融入黑色。
- **不要实心细边框**：玩家多次反馈实心边框显得生硬。

## 2. 调查员区域（左下）

- 整个调查员区域是一个整体：资产槽、肖像、技能、名字、token 同属一个黑块。
- 资产槽每个槽是一个小方块，图标和"空余/总数"写在方块内部。
- 槽位不要超出黑块边界（每个槽宽 52，间距 10）。

## 3. 右上角调查员头像

- 用**方形边框**，不要圆形奖章。
- 颜色语义：琥珀色 = 当前视角；绿色 = 等待操作；其余变暗（60% 透明）。

## 4. 数值变化的反馈

- **伤害和恐惧**：不要全屏闪红。做法：一个带图标的小标签（图标 + "-N"）从桌面中央飞到对应的 token，落地时 token 脉冲。
  - 在哪：`TableScreen.Render.cs` `FlyChip`。
  - 注意：标签飞行在检定面板打开时会被挡住，验证前先关掉弹窗（QA 的 `close`）。
- **消耗资源**：资源 token 脉冲（缩放 1.28 回落），并飘出"-N 资源"。
- **资源不足**：点击打不出的手牌时，手牌左右抖动，资源 token 闪红，并提示"需要 N，现有 M"。
- 所有动效在 `ReducedMotion` 设置开启时缩短或关闭。

## 5. 目标区（顶部）

- 目标名旁边要有进度，和毁灭进度一致的表达：一排图标，已达成的亮，未达成的暗，右侧写"当前 / 需要"。
  - 线索进度用线索 token 图标；毁灭用圆点。
- 悬停目标区弹出浮窗：目标名、推进条件（写清楚是全队还是个人）、场景文字。
  - 场景文字统一放在 `ScenarioData.Intro`，准备界面和浮窗共用。

## 6. 分摊线索（团队付费）窗口

- 图片化：每位调查员一行，左边肖像，中间线索 token（每个要花的线索一个图标），两侧 ±。
- 上方一行显示"需要 N 个线索 · 已选 M"，用线索图标。
- 调查员名字用中文（`m.Name(inv)`），不要显示核心返回的英文标签。

## 7. 准备界面（选人与难度）

- 选人区是左边 2 × 2 田字格（最多 4 人），混乱袋在右边。
- 底部按钮（返回、开始）必须在屏幕内：纵向预算要算好，肖像高度要压缩（当前 120）。
- 混乱袋：显示该难度的全部标记（按数量），下面列出本关特殊标记的惩罚文字（取自冒险卡）。
- 卡组选择笔记：放在人物信息的对侧，每个卡组一个两行横条（头像、标题为卡组名、第二行为"张数 · 种数 · 经验"），边框颜色按阵营（守护者蓝、探求者橙、流浪者绿、神秘者紫、生存者红）。

## 8. 通用原则

- **界面文字全部中文**：核心的英文标签（如 "Roland Banks"）不能直接显示，要换成本地化名字。
- **不要静默替玩家做选择**：DLL 发出的问题（如 `PickScenarioSettings`）如果前端直接用默认值回答，玩家看不见。这是一个待修的缺口。
- **布局先算预算再摆放**：屏幕 1080 高，底部按钮、标题、内容各占多少要先算，避免内容挤出屏幕。
- **验证动效要抓中途帧**：用 QA 步骤触发效果后 0.1–0.3 秒截图；截图前关掉挡住的弹窗。

## 9. 验证方法（给后面关卡用）

- 用 QA 脚本（`fx:`、`move:`、`close`、`capture`）触发效果并截图，比等自动通玩更快。
- 自动通玩的审计日志（`AUDIT question=… choiceTags=…`）用来确认 DLL 的问题类型都有前端处理。
- 截图目录：`evidence/ui-review/`。

## 10. 手牌

- **检定时仍是扇形**：检定状态只抬高手牌，不取消弧度和旋转。取消旋转会让手牌变成平行，玩家看不出是手牌区。
- **手牌底部渐变**：手牌区最底层放一个从下往上变暗的渐变，手牌在它上面。
  - 注意：旧的底部渐变代码在未调用的 `InvestigatorPanel` 里，因此一度消失。
- **牌多时的排版**：超过 8 张时，弧度压平（下垂上限 26 px，旋转 ±11°），保证外侧的牌不掉出手牌区。10 张和 14 张已截图确认都在区域内；牌多时名字会被遮住一部分，这一点待你判断。
- 验证方法：QA 步骤 `handpad:N` 把手牌复制到 N 张后截图（仅测试用，正常游戏里为 0）。
