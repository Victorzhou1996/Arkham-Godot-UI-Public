## 1. 设计要点
### 1.1 视觉
- 风格基准：参考版（暖色厚涂背景、炭黑黄铜面板、象牙纸按钮、自绘混沌 token、霞鹜文楷/思源宋体）。
- 场景背景只用纯场景图，按规则状态切换（书房/走廊/走廊屏障/阁楼/地窖/客厅），不做人物入景图。
- 混沌 token 用网页版素材；资源/线索/伤害/恐惧等信息标记沿用半成品的标记样式。
- 组卡界面保留半成品布局，换成参考版材质与配色。

### 1.2 文字清晰（重点）
半成品的问题：卡图大而文字糊。原因是大图被缩小时没有 mipmap、缩放比不合适，且没有可替代的文字层。新版对策：
1. 卡图使用最高清源图（核心盒 1619×2321 webp；遭遇卡由 AVIF 转换），导入时开启 mipmap，显示用线性 mipmap 过滤，避免缩小后发糊、出锯齿。
2. 三档尺寸：手牌常态（看图与名称）、悬停放大（高度 ≥ 560px，正文可读）、单击阅读器（全高大图＋右侧中文规则文本，用矢量字体排版）。
3. 所有界面文字 1080p 下最小 18px；叠在插画上的文字一律加底板或描边阴影。
4. 交付前用 1920×1080 与窄窗口各截图，放大检查手牌、阅读器、行动窗口的文字。

### 1.3 交互
- 卡牌：单击投入/打出，或拖动投入；拖动时卡牌跟随抓取点；放置区命中范围宽松；自己投入的牌可拖回撤回。
- 头像可点开调查员卡大图。
- 右侧行动窗口：列出当前可执行行动，场上目标用箭头指示；多触发与需要排序的效果由玩家选择。
- 自动略过：仅当"只有一个合法选项且该选项不需要玩家决定"（如唯一的强制效果、唯一的"跳过/应用结果"）时自动回答；凡是有排序、目标或可选性的，一律交给玩家。

## 2. 架构
```
app/          Godot 4.5.1 Mono 工程（Arkham.App.csproj）
  Scenes/     界面场景与组件（C#）
  Style/      主题、材质、着色器、字体
  assets/     背景、卡图、token、参考版素材
engine/       引擎适配层（复制自半成品 engine/，重审 AutomaticIndex）
  View/       视图模型层：与剧本无关的牌桌数据
  Flow/       交互路由层：问题类型 → 操作方式、自动略过策略
  Scenario/   剧本数据（每关一个 json：背景路由、热点、剧情图）
probe/        无界面流程探针
runtime/      规则 DLL 与宿主（复制，哈希核对）
qa-data/      隔离测试档案
docs/ evidence/ jobs/ tools/
```
工具链：`godot-native-20261019/tools` 下的 dotnet、nuget、Godot 4.5.1 Mono（通过 `tools/night-runner.ps1` 执行）。
