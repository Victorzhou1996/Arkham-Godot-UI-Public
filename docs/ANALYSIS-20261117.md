- Godot 4.7.2 导出包，未加密；1030 个文件。前端为 GDScript 字节码（175 个 .gdc，标识符与中文字符串完整可读），场景几乎全在代码里构建。

## 3. 决定

### 3.1 后端
只用我们的规则 DLL（经 NativeHost）。不改规则 DLL、存档格式、规则身份、撤回语义与回答权限。

### 3.2 技术栈
Godot 4.5.1 Mono + C#，沿用工作区现有工具链与 NativeHost。参考程序的代码只当阅读材料，所以不需要升级到 4.7。

### 3.3 卡牌图像：用原版卡图作卡面，参考版风格做外围
- 理由：后续每个剧本都有大量遭遇卡、地点、敌人。参考版那种"空卡框＋裁切插画＋重排文字"的卡面需要逐张制作，无法持续；原版卡图 7395 张已经齐全，零逐卡成本。
- 卡面统一显示原版卡图，外层（手牌扇、悬停放大、选中金框、可执行高亮、桌面材质、按钮与面板）用参考版风格。
- 可读性：悬停放大到能读清规则文字；单击打开阅读器，左侧大卡图，右侧用 `localization/zh-CN/cards.json` 的中文文本以清晰字体排出。
- 第一关之后如需要，可再为玩家卡加一套参考版风格的重绘卡面作为可选皮肤，不作为基础依赖。

### 3.4 分层架构（为后续剧本设计）
1. **引擎适配层**（沿用 `engine/`）：DLL ↔ 游戏状态 + 待回答问题。
2. **视图模型层**（新，C#，与剧本无关）：从引擎状态生成地点、敌人、调查员、手牌、场景/密谋、混沌袋、标记等通用数据。地点排布直接用引擎提供的 `locationLayout` 网格（网页版 `Scenario.vue` 就是这样做的），不手写每关地图逻辑。
3. **交互路由层**（新，C#，与剧本无关）：把每一类问题映射到固定的操作方式：点场上目标、投入卡牌（单击/拖动）、右侧行动窗口选择、多触发排序、伤害/恐惧分配、数量选择、阅读剧情。自动跳过集中在这里：只有"唯一合法选项且不需要玩家决定"才自动处理；多个需排序/选择的效果交给玩家。以网页版的问题覆盖面为清单。
4. **表现组件**（新，按参考版风格）。
5. **剧本数据**（每关一份数据文件，不写代码）：背景图、按规则状态切换背景（如走廊→屏障）、剧情插画、地点在背景上的热点位置（可选）。

后续剧本的工作量主要是第 5 层的数据与美术，加上偶尔出现的新交互类型。
